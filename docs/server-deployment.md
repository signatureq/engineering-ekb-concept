Рабочий VPS: Ubuntu, `176.12.67.40`, исходники в `/opt/orion/site`, Compose-проект **`orion`**. Для Laravel всегда использовать оба файла:


`server/.env.filament` создаётся по `server/.env.filament.example`, права `600`. Задать уникальный постоянный `APP_KEY`, `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` и `PUBLIC_SITE_URL` с основным HTTPS-доменом, а также прежний `INQUIRY_TO_EMAIL`. Пример уже указывает SQLite, приватное хранилище, файловые сессии, безопасную cookie и совместимый обработчик паролей. Секреты не включать в Git или публичную сборку.

**Сохранить `server/.env`** с правами `600`: Caddy по-прежнему читает из него `SITE_ADDRESS`, `SERVER_IP` и `SITE_ROBOTS_POLICY`. Это отдельный файл от Laravel env. При изменении env пересоздать затронутый контейнер. Ключ приложения сохранять между обновлениями и при восстановлении.

`server/start-filament.sh` создаёт каталоги хранения, назначает владельца `www-data`, применяет миграции и кеширует конфигурацию/шаблоны. Он **не импортирует данные и не пересобирает публичный сайт**: для этого предусмотрены отдельные команды ниже. База хранит время в UTC; интерфейс и даты заявок показывают Екатеринбург.

## Первый перенос с Django

Переносить свежую согласованную production-копию, не локальную проверочную базу. На финальное копирование и переключение приостановить работу редактора. Сохранить старые исходники/образ, Django-том и Caddy-тома. Не применять `docker compose down -v`.

1. Обновить исходники, подготовить приватный `.env.filament`, установить актуальный `server/backup.sh` для таймера. Пока активна Django-версия, файл `server/.filament-active` должен отсутствовать. Запустить `bash server/backup.sh`; новая копия появится в `/var/backups/orion/<UTC-метка>/`. Проверить целостность копии, сохранить её приватно.
2. Указать фактический каталог свежей копии и сделать частный JSON-экспорт. Этот файл содержит пользователей, хеши паролей и черновики; он остаётся вне web-root:

```sh
backup_dir=/var/backups/orion/ACTUAL_UTC_TIMESTAMP
python3 scripts/filament_export_django.py "$backup_dir/cms.sqlite3" --output "$backup_dir/filament-transfer.json"
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml build
```

3. Подготовить отдельный Laravel-том, не запуская новый web поверх действующего сайта. Следующая команда применяется только к новому пустому тому. В существующей Laravel-базе повторный импорт запрещён:

```sh
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml run --rm --no-deps cms sh -c 'mkdir -p /data/media /data/builds /data/storage/framework/cache/data /data/storage/framework/sessions /data/storage/framework/views /data/storage/logs && touch /data/cms.sqlite && php cms/artisan migrate --force && chown -R www-data:www-data /data'
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml run --rm --no-deps --volume "$backup_dir:/import:ro" cms php cms/artisan cms:import /import/filament-transfer.json --media=/import/media
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml run --rm --no-deps cms php cms/artisan cms:build
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml run --rm --no-deps cms chown -R www-data:www-data /data
```

Импорт сохраняет ID, адреса, даты, опубликованные снимки, черновики, блоки, связи, галереи, настройки и учётные записи. Старые исходные фотографии получают приватные копии для редактора; простое сохранение не меняет их публичные адреса. Загруженные ранее фотографии берутся из той же резервной копии. Повторный импорт не восстанавливает удалённые материалы и не перезаписывает правки редактора.

Хеш Django PBKDF2 проверяется новым приложением; после успешного входа Laravel обновляет его до bcrypt только в новой базе. Исходная Django-база и прежний пароль для отката не меняются. Не создавать взамен импортированного `orion` тестовую учётную запись.

4. Только после успешного импорта и сборки переключить сервисы. Проект и имена `cms/web/edge` остаются прежними, Caddy использует прежние HTTPS-данные:

```sh
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml up -d --force-recreate
touch server/.filament-active
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml logs --tail=100 cms web edge
```

5. Проверить доверенный HTTPS, открытие сайта, вход прежним `orion`, списки материалов, фотографии и ресурсы, сборку из опубликованных снимков, GET `/api/inquiry/`, приватность базы/media и новую резервную копию в Laravel-режиме. Полный сценарий сохранения, предпросмотра, публикации и снятия материала проверять на изолированной копии. Возобновить работу редактора после проверки. При выполненном переключении 19 октября проверочную статью на production не создавали и не публиковали; локальный `ship` дополняется отдельными live-проверками из production-записи.

Если подготовка/импорт/сборка завершились ошибкой, не переключать действующий web. Исправить причину и использовать согласованную копию; не пытаться повторно импортировать поверх заполненной Laravel-базы.

## Обычное обновление Laravel

Сначала создать приватную резервную копию, затем обновить исходники. Проверки локальной версии: `cd cms` и `php artisan test --compact`; для публикации нужен также рабочий Python с зависимостями из `requirements.txt` и Pillow. Docker-образ содержит нужный runtime и проверку синтаксиса скриптов при сборке.

Из `/opt/orion/site`:

```sh
bash server/backup.sh
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml up -d --build --force-recreate
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml exec -u www-data cms php cms/artisan cms:build
docker compose -p orion -f server/compose.filament.yaml -f server/compose.edge.yaml logs --tail=100 cms web
```

`cms:build` собирает только опубликованные снимки и не публикует черновики. При ошибке сборки прежняя публичная версия сохраняется. Текущая и две предыдущие полные сборки остаются в томе. После изменения шаблонов или публичных ресурсов явная пересборка обязательна.

## Резервные копии и восстановление

`server/backup.sh` выбирает Laravel по наличию **`server/.filament-active`**; без него используется Django. Маркер должен соответствовать реально работающему приложению. В Laravel-режиме вызывается `php cms/artisan cms:backup --output=<новый-каталог>`. Команда делает согласованную SQLite-копию и копирует приватные фотографии под блокировкой публикации. Резервная база называется **`cms.sqlite3`** в обоих режимах; у работающего Laravel путь другой: **`/data/cms.sqlite`**.

Ежедневный `orion-backup.timer` запускается около 03:20 UTC с задержкой до десяти минут. `/var/backups/orion` имеет права `700`, файлы базы/env — `600`; срок хранения около 14 дней. Копия содержит базу, `media/`, `deployment.env` (прежний `.env`) и, для Laravel, `filament.env`. Данные пользователей и черновиков остаются приватными. Эти копии находятся на том же VPS; настроенного управляемого внешнего хранилища нет.

Установка/обновление таймера:

```sh
install -m 750 server/backup.sh /usr/local/sbin/orion-backup
install -m 644 server/orion-backup.service server/orion-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now orion-backup.timer
systemctl start orion-backup.service
systemctl list-timers orion-backup.timer
```

Для ручной копии достаточно `bash server/backup.sh`. Проверять SQLite-копию можно командой `sqlite3 /var/backups/orion/ACTUAL_UTC_TIMESTAMP/cms.sqlite3 'PRAGMA integrity_check;'`: ожидается `ok`. Приватную внешнюю копию передавать только защищённым способом и хранить отдельно от публичных артефактов.

Для восстановления Laravel остановить редактирование и `cms/web`, сохранить копию повреждённого состояния, выбрать базу и media **из одной резервной копии**. В Laravel-том поместить `cms.sqlite3` как `/data/cms.sqlite`, вернуть `media/`, прежний `APP_KEY` и остальные production-параметры из `filament.env`; Caddy-конфигурацию восстановить из `deployment.env` при необходимости. Сохранять права приватных файлов и владельца `www-data` (в текущем Debian-образе UID/GID 33). Удалённые сессии/кеш создаются заново. Применить миграции, выполнить `cms:build`, затем запустить приложение и проверить вход/фотографии до возврата редактора. Сам запуск сборку не выполняет.

## Откат на сохранённый Django

Этот путь нужен для сохранённой версии, а не для новых обновлений. Остановить редактирование, сделать свежую Laravel-копию и сохранить новый том. Django-том `orion_cms-data` не удалялся и содержит состояние до переключения. Изменения, сделанные уже в Laravel, автоматически в старую базу не переносятся; перед откатом учитывать их отдельно.

Вернуть сохранённую совместимую версию Django-образа/исходников и прежний `server/.env`, затем:


Проверить HTTPS, вход, данные и фотографии. Старая база хранит прежний PBKDF2-хеш и не затронута bcrypt-обновлением в Laravel. Старый startup применяет Django-миграции, однократный `seed_content` и сборку; legacy-команды `python server/manage.py ...` относятся только к этому пути. Для восстановления Django из backup рабочее имя базы `/data/cms.sqlite3`, прежний владелец UID 1000. Оба редактора одновременно не использовать.

## Заявки через FormSubmit

Серверный `/api/inquiry/` сохраняет прежний контракт: GET возвращает доступность и CSRF-токен, POST принимает форму. Получатель задаётся **в `server/.env.filament`** как `INQUIRY_TO_EMAIL`; пустое значение выключает отправку. В публичной форме и JavaScript почты нет. После изменения env пересоздать `cms`.

`PUBLIC_SITE_URL` остаётся прежним основным HTTPS-origin и используется в исходящих Origin/Referer. Владелец уже активировал FormSubmit для этого адреса. При новой активации ответ возвращает ошибку настройки; успех требует явного `success: true` или `"true"`. Отказ/таймаут сохраняет заполненную форму. Принятие провайдером и фактическое появление в почтовом ящике — разные проверяемые события.

В Laravel поддержан существующий заголовок `X-CSRFToken`; браузер отправляет вложения под именем **`files[]`**, чтобы PHP принял все файлы. Допускается до пяти вложений общим размером до 10 МБ; файлы не попадают в публичный каталог. Письмо имеет русские подписи, полное принятое многострочное сообщение, имена всех вложений, дату по Екатеринбургу и UUID. Перечень услуг берётся только из опубликованных снимков. Nginx ограничивает частоту; сервер проверяет CSRF, поля, длины, расширения и ловушку для ботов. Заявки не архивируются в CMS и не ставятся в очередь; UUID помогает сопоставить письмо, но не гарантирует отсутствие дубля после сетевого сбоя.

Проверки без реальных писем:

```sh
cd cms
php artisan test --compact --filter=InquiryDeliveryTest
```

MAX и адрес появятся на сайте после заполнения и публикации в «Контакты компании»; пустые значения не создают заглушек. Ссылка MAX проверяется как HTTPS-ссылка профиля max.ru. Поле телефона принимает уже используемый формат со скобками.

H2 на страницах статей теперь принадлежат только основному тексту. Служебные подписи и рекомендации сохраняют оформление без H2. Страница «Как работаем» использует существующие редактируемые тексты, фотографию (можно заменить в редакторе страницы), последовательность из четырёх этапов и блок подготовки. Для выпуска пройдены 29 Laravel-тестов / 219 проверок, Pint и шесть Python-проверок статической сборки. Данные для MAX и адреса клиент предоставит позже.
